# مواصفة تصميم Jeerah Smart Demo

التاريخ: 3 أغسطس 2026

الحالة: جاهزة لمراجعة المستخدم قبل خطة التنفيذ

المرجع البصري المعتمد: [Living Neighborhood](assets/jeerah-living-neighborhood-mobile.png)

## 1. الهدف

بناء نسخة تجريبية مقنعة ومتكاملة من Jeerah Smart تتكون من سطحين مترابطين:

- تطبيق سكان قابل للتثبيت كتطبيق ويب تقدمي (PWA) على الجوال.
- لوحة إدارة متجاوبة لإدارة العقارات والوحدات والسكان والمصاريف والخدمات.

النسخة Frontend-only ولا تتضمن خادم إنتاج، لكنها تتصرف كمنتج فعلي: جميع النماذج والأزرار والتنقلات الأساسية تعمل، والبيانات تتغير وتبقى محفوظة محليًا، كما تتزامن لوحة الإدارة والتطبيق بين تبويبات المتصفح.

استراتيجية النطاق هي **عمق في الرحلات الذهبية واتساع مقنع في بقية المنتج**. تعمل ثلاث رحلات من البداية إلى النهاية بكل الحالات: دفع فاتورة، حجز خدمة ومتابعتها، ونشر محتوى من الإدارة وظهوره في التطبيق. بقية الأقسام تحتوي على بيانات وتفاعلات محلية حقيقية، دون محاولة بناء بنية إنتاج خلفية.

## 2. مبادئ المنتج

1. **مقنع من أول دقيقة:** بيانات واقعية، صور عالية الجودة، حالات متعددة، وعدم وجود صفحات فارغة أو أزرار ميتة في المسارات الأساسية.
2. **منتج واحد بوجهين:** ما يفعله المدير ينعكس في تطبيق الساكن، وما يفعله الساكن يحدّث لوحة الإدارة.
3. **ديمو آمن وواضح:** تجربة الدفع تشبه التدفق الحقيقي، لكنها لا تجري خصمًا حقيقيًا ولا تطلب بيانات بطاقة فعلية.
4. **هوية مميزة لا تبدو مولّدة:** نظام بصري منضبط، صور متناسقة، وأيقونات من مكتبة احترافية واحدة.
5. **العربية أولًا دون إهمال الإنجليزية:** دعم AR/EN واتجاه RTL/LTR في جميع الشاشات الأساسية.
6. **قابل للتجربة على أي جهاز:** الجوال هو الأولوية للتطبيق، وسطح المكتب هو الأولوية للإدارة، مع استجابة كاملة لكليهما.

## 3. الاتجاه البصري المعتمد

### تطبيق السكان

- هوية “Living Neighborhood” بأزرق ليلي عميق، أزرق كوبالت، أخضر نعناعي، ولمسة مرجانية دافئة.
- خلفية علوية مع صورة معمارية سعودية ونمط هندسي هادئ؛ المحتوى يبقى واضحًا عالي التباين.
- وحدة رئيسية لـ **نبض المجتمع** تعرض صحة المبنى والمصاريف القادمة والحالة التشغيلية.
- تجميع المحتوى بمساحات وفواصل خفيفة بدل تحويل كل عنصر إلى بطاقة مستقلة.
- أيقونات `Phosphor Duotone` الأصلية من مكتبة واحدة، بأحجام وأوزان بصرية ثابتة.
- لا تُرسم شعارات أو أيقونات العلامات التجارية يدويًا ولا تُولّد بالذكاء الاصطناعي.

### لوحة الإدارة

- شريط تنقل داكن يحمل نفس الهوية، مع سطح محتوى فاتح عالي الكثافة وسهل القراءة.
- بطاقات مؤشرات محدودة، جداول واضحة، فلاتر عملية، وحالات فارغة تحتوي على إجراء مباشر.
- لا يظهر درج جانبي فوق المحتوى على الجوال؛ يتحول إلى Drawer كامل قابل للإغلاق دون ضغط الصفحة أو إنشاء تمرير أفقي.
- نظام الاتجاه والمحاذاة يتغير كاملًا عند اختيار العربية، وليس النص فقط.

### الحركة والمؤثرات

- نبض محيطي هادئ لحالة المجتمع.
- عدّ تصاعدي للمبالغ والمؤشرات عند الدخول.
- دخول متتابع للعناصر بزمن قصير.
- مؤشر التنقل السفلي ينزلق بين الأقسام.
- ضغطات بأثر Spring خفيف، ونقطة إشعار تتحرك مرة واحدة فقط.
- تأثير إضاءة عابر ومحدود على زر الدفع الأساسي.
- Parallax خفيف للصورة المعمارية عند التمرير.
- جميع الحركات تحترم `prefers-reduced-motion` ولا تمنع الاستخدام.

## 4. بنية التجربة

سيُبنى المشروع فوق قالب Product Design `mobile-app` مع الحفاظ على Runtime الخاص به، ثم تُضاف مسارات الإدارة داخل التطبيق نفسه. البنية المقترحة:

- React + TypeScript + Vite.
- React Router لمسارات التطبيق والإدارة.
- Zustand لحالة الواجهة والبيانات المحلية.
- IndexedDB لحفظ بيانات الديمو، مع BroadcastChannel للمزامنة الفورية بين التبويبات.
- Motion للحركات الدقيقة.
- Phosphor Icons للأيقونات الوظيفية.
- Recharts أو مكتبة مخططات خفيفة لمؤشرات الإدارة.
- `vite-plugin-pwa` للـ manifest وservice worker والتثبيت والعمل دون اتصال جزئيًا.
- طبقة Domain مشتركة تفصل البيانات والمنطق عن المكونات المرئية.

### تدفق البيانات المترابط

1. المدير ينشئ مصروفًا أو إعلانًا من لوحة الإدارة.
2. طبقة Demo Store تحفظ الحدث في IndexedDB.
3. BroadcastChannel يبلغ تبويب تطبيق الساكن فورًا.
4. يظهر المصروف أو الإعلان في الصفحة الرئيسية والإشعارات.
5. عند دفع المصروف تجريبيًا، تتغير حالته إلى Paid ويصل التحديث إلى لوحة الإدارة ومؤشراتها.

يوجد زر **Reset demo** يعيد جميع البيانات إلى البذور الأصلية في أي وقت.

## 5. مسارات تطبيق السكان

### الدخول والتجهيز

- تسجيل دخول تجريبي مع تعبئة سريعة للحساب النموذجي دون تخزين كلمات مرور حقيقية.
- شاشة ترحيب قصيرة تشرح نبض المجتمع والتثبيت على الجوال.
- اختيار اللغة، المبنى الافتراضي، وتفضيلات الإشعارات.

### الصفحة الرئيسية

- تحية شخصية، مبنى نشط، صورة المبنى، وCommunity Pulse.
- المصروف القادم وإجراء الدفع المباشر.
- إجراءات سريعة: المصاريف، الخدمات، الانضمام بكود، الزوار.
- نشاط المجتمع وإعلانات الإدارة.
- اقتراح سياقي واحد مبني على حالة البيانات، مثل إكمال دفع أو متابعة طلب.

### المباني والشقق

- قائمة العقارات المرتبطة بالساكن.
- صفحة مبنى مع معرض صور، العنوان، المدير، المرافق، صحة المبنى، والوحدات.
- صفحة وحدة سكنية مع بيانات افتراضية آمنة، العقود النموذجية، والطلبات المرتبطة.
- معرض صور للشقق واللوبي والمرافق والمواقف والمساحات المشتركة.

### المصاريف والدفع

- فلاتر: مستحق، مدفوع، قادم، ومتأخر.
- تفاصيل الفاتورة مع البنود، الضريبة، الرسوم، تاريخ الاستحقاق، ورقم مرجعي.
- اختيار وسيلة الدفع، مراجعة نهائية، معالجة، نجاح، انتظار، رفض، وإعادة المحاولة.
- إيصال قابل للطباعة أو التنزيل بعد الدفع التجريبي.
- سجل معاملات يعرض الطريقة والحالة والرقم المرجعي.

### السوق والخدمات

- فئات: صيانة، تنظيف، تكييف، كهرباء، سباكة، نقل، وتشطيبات.
- مزودون نموذجيون بتقييمات وأسعار وصور وأوقات وصول متوقعة.
- صفحة تفاصيل، اختيار موعد، إضافة ملاحظات وصور نموذجية، تأكيد الطلب، وتتبع الحالة.
- حالات الطلب: جديد، تم قبوله، في الطريق، جاري التنفيذ، مكتمل، وملغي.

### المجتمع والعمليات

- إشعارات وإعلانات قابلة للقراءة والأرشفة.
- استفتاء مجتمعي نموذجي بنتيجة ونسبة مشاركة فورية، وحدث مع RSVP.
- سجل زمني للصيانة مع صور قبل/بعد وحالة كل خطوة.
- تصريح زائر تجريبي مع QR صالح لمدة محددة.
- حجز مرفق نموذجي، مثل النادي أو قاعة الاجتماعات، مع اختيار موعد وتأكيد.
- الملف الشخصي، طرق الدفع التجريبية، الإعدادات، اللغة، والمساعدة.

### التثبيت كتطبيق

- صفحة Install App مخصصة تشرح المزايا وتكتشف نوع الجهاز.
- زر تثبيت مباشر على المتصفحات الداعمة لـ `beforeinstallprompt`.
- تعليمات مرئية مختصرة لـ Safari على iPhone وiPad لإضافة التطبيق إلى الشاشة الرئيسية.
- manifest بأيقونات مناسبة واسم مختصر وtheme colors وstart URL لمسار التطبيق.
- Offline shell يعرض البيانات المحفوظة وآخر مزامنة، مع منع العمليات التي تحتاج اتصالًا وإظهار سبب واضح.

## 6. مسارات لوحة الإدارة

- **Dashboard:** مؤشرات التحصيل، المصروفات المفتوحة، الطلبات، الإشغال، نشاط حي، ومخطط اتجاه.
- **Properties:** العقارات، الصور، المرافق، الصحة، والمديرون.
- **Units & Residents:** الوحدات والسكان والحالات والبحث والفلاتر.
- **Expenses:** إنشاء وتعديل ونشر المصاريف ومتابعة التحصيل.
- **Payments:** قائمة المعاملات، الطريقة، الحالة، المبلغ، والإيصال.
- **Orders:** متابعة طلبات الخدمات وتغيير حالاتها.
- **Marketplace:** المزودون والفئات والأسعار والتقييمات.
- **Announcements:** إنشاء إعلان ونشره ومشاهدة أثره داخل تطبيق الساكن.
- **Visitor & Amenities:** تصاريح الزوار وحجوزات المرافق.
- **Analytics:** التحصيل، أزمنة الإغلاق، الطلبات حسب الفئة، وصحة المباني.
- **Audit Log:** سجل محلي واضح لإنشاء المصاريف والدفع وتغيير حالات الطلبات والنشر.
- **Settings:** اللغة، المظهر، صلاحيات نموذجية، إدارة بيانات الديمو، وإعادة الضبط.

كل عمليات الإنشاء والتعديل والحذف الأساسية تعمل محليًا مع رسائل نجاح وفشل، وتحديث فوري للجداول والمؤشرات.

## 7. تجربة الدفع التجريبية

### الوسائل والعلامات

- Apple Pay.
- mada.
- Visa.

تُستخدم شعارات رسمية أو حزم أيقونات علامات تجارية موثوقة، مع احترام الأبعاد والمساحات الآمنة والألوان. لا تُعاد رسم الشعارات ولا تُولّد كصور تقريبية.

### السلوك

- Apple Pay يظهر كزر دفع معتمد بصريًا، ثم ينتقل إلى خطوة تأكيد داخل الديمو؛ لا تتم محاكاة نافذة نظام Apple الأصلية بشكل مضلل.
- mada وVisa يعرضان بطاقات اختبار مقنّعة، وخيار إضافة بطاقة تجريبية مع تحقق من التنسيق وحالة 3-D Secure نموذجية.
- تتضمن البيانات وسيلتين محفوظتين فقط: `mada •••• 4455` و`Visa •••• 4242`، دون وجود رقم كامل أو CVV في التخزين.
- لا تُقبل أو تُحفظ بيانات بطاقة حقيقية، ويظهر تنبيه واضح: “Demo payment — لا تستخدم بطاقة حقيقية”.
- يمكن للمستخدم اختيار نتيجة السيناريو: نجاح، Pending، أو Declined من لوحة Demo Scenario غير ظاهرة للمستخدم العادي.
- يدعم السيناريو كذلك الإلغاء وانتهاء المهلة والاسترداد، مع OTP تجريبي معلن داخل الواجهة عند اختيار mada.
- تستمر حالة Processing مدة قصيرة واقعية، ثم يظهر إيصال وحركة نجاح وتحديث للرصيد.
- حالة الرفض تشرح السبب وتوفر إعادة المحاولة أو تغيير الوسيلة.

## 8. بيانات وصور الديمو

جميع الأسماء والأرقام والعناوين خيالية ولا تستخدم بيانات عملاء حقيقية. تحتوي البذور على الأقل على:

- 4 عقارات بأنماط مختلفة و12 وحدة.
- 8 سكان وحالات إشغال متعددة.
- 10 مصاريف موزعة بين مستحق ومدفوع ومتأخر وقادم.
- 12 دفعة ناجحة ومعلقة ومرفوضة عبر Apple Pay وmada وVisa.
- 8 مزودي خدمات و10 طلبات بحالات متنوعة.
- 6 إعلانات وإشعارات ذات أولويات مختلفة.
- 5 تصاريح زوار و6 حجوزات مرافق.
- 12 نشاطًا زمنيًا لصيانة ومجتمع.

### حزمة الصور

تُنشأ عبر ImageGen مجموعة متناسقة من 12 إلى 15 صورة فوتوغرافية عالية الجودة خصيصًا للديمو، وتشمل:

- واجهة برج سكني سعودي حديث ليلًا ونهارًا.
- مجمع سكني متوسط الارتفاع.
- لوبي فاخر، غرفة معيشة، مطبخ، وممرات.
- نادي رياضي، مسبح، موقف سيارات، وقاعة اجتماعات.
- فني صيانة في موقع عمل وصور قبل/بعد.
- صور خدمات للتنظيف والتكييف والكهرباء.

تُحفظ الصور محليًا بصيغة WebP وبأحجام مناسبة، مع نصوص بديلة، ولا تُستخدم صور عامة عشوائية متفاوتة الأسلوب.
يوثق ملف `CREDITS.md` مصدر كل أصل، بما في ذلك الأصول المولدة وأصول شعارات الدفع الرسمية.

## 9. الميزات المميزة

### Community Pulse

مؤشر مفهوم من 0 إلى 100 يُحسب محليًا من ثلاثة عوامل واضحة: تحصيل المصاريف، حالة الصيانة، والتنبيهات المفتوحة. يمكن فتحه لفهم سبب النتيجة بدل أن يكون رقمًا زخرفيًا.

### Live Twin Demo

التطبيق والإدارة يتزامنان فورًا بين تبويبين. نشر إعلان، إنشاء فاتورة، دفعها، أو إغلاق طلب يظهر على السطح الآخر دون تحديث الصفحة.

### Scenario Studio

لوحة ديمو صغيرة ومحمية باختصار أو زر إعدادات تسمح بتبديل السيناريو بالكامل: يوم طبيعي، دفعة مستحقة، صيانة عاجلة، إعلان طارئ، أو مجتمع مستقر. هذا يتيح استعراض معظم الحالات بسرعة.

### Maintenance Story

كل طلب صيانة يتحول إلى قصة زمنية: البلاغ، قبول الفني، الوصول، صورة قبل، الإنجاز، صورة بعد، وتقييم الساكن.

### Suggested Next Action

يعرض التطبيق إجراء واحدًا مناسبًا للسياق بدل قائمة توصيات مزدحمة، مثل “ادفع قبل 5 أيام” أو “قيّم الخدمة المكتملة”. لا يُقدَّم على أنه ذكاء اصطناعي.

### Neighbor Deals

عينة تفاعلية لصفقة جماعية تنخفض تكلفتها عند انضمام عدد أكبر من سكان المبنى، مثل تنظيف المكيفات. تظهر مرحلة التقدم والحد الأدنى دون إضافة نظام تجارة إلكترونية جديد.

### Demo Tour

جولة قصيرة اختيارية توجّه المستخدم إلى أفضل نقاط العرض، مع زر تخطي وعدم تكرارها بعد الإغلاق.

## 10. حالات الخطأ والحالات الفارغة

- لا توجد بيانات، لا توجد نتائج بحث، اتصال ضعيف، Offline، خطأ في الحفظ، ومدخلات غير صالحة.
- فشل الدفع، انتهاء الجلسة التجريبية، وتعارض تحديث بين تبويبين.
- Skeletons للتحميل القصير، ورسائل خطأ قابلة للتنفيذ بدل النصوص العامة.
- جميع الأزرار الحرجة تمنع النقر المتكرر أثناء المعالجة.
- إذا تعذر استرجاع IndexedDB، ينتقل التطبيق إلى نسخة ذاكرة مؤقتة ويعرض تحذيرًا قابلًا للإخفاء.

## 11. الوصول والجودة اللغوية

- تباين WCAG AA، أهداف لمس لا تقل عن 44×44، وتنقل كامل بلوحة المفاتيح.
- أسماء وصول للأزرار الرمزية وحقول OTP والدفع.
- ترتيب Focus منطقي وإعلانات `aria-live` للحفظ والدفع والتحديثات.
- RTL حقيقي للجداول والرسوم والمسارات، مع بقاء الأرقام والعملات وشعارات الدفع صحيحة الاتجاه.
- لا تظهر مفاتيح ترجمة خام أو placeholders مثل `{{total}}`.
- تنسيق SAR والتواريخ والأرقام حسب اللغة.

## 12. الاختبار ومعايير القبول

### اختبارات آلية

- وحدات التنسيق والحساب وCommunity Pulse.
- انتقالات حالات الفاتورة والدفع والطلب.
- Seed/reset والمزامنة بين التبويبات.
- تحقق النماذج ومسارات الخطأ الأساسية.
- بناء الإنتاج وفحص PWA manifest وservice worker.

### تحقق بصري وتفاعلي

- مقارنة لقطات المصدر والمرجع البصري والتطبيق المبني بالحجم نفسه.
- فحص التطبيق على عرض 390 و430 و768 بكسل.
- فحص الإدارة على 1440 و1024 و390 بكسل.
- تجربة العربية والإنجليزية، الاتجاه، لوحة المفاتيح، وReduced Motion.
- تجربة تثبيت PWA على متصفح داعم والتحقق من تعليمات iOS.
- فتح الإدارة والتطبيق في تبويبين وإثبات التزامن في السيناريوهات الأساسية.

### تعريف النجاح

تُعد النسخة جاهزة عندما يستطيع المستخدم تنفيذ الرحلات التالية دون أزرار ميتة:

1. تسجيل الدخول، استعراض مبنى وصوره، فتح فاتورة، دفعها تجريبيًا، وتنزيل الإيصال.
2. اختيار خدمة، إنشاء طلب، وتتبع حالته حتى الإكمال.
3. إنشاء تصريح زائر أو حجز مرفق.
4. إنشاء مصروف وإعلان من الإدارة ومشاهدتهما فورًا في التطبيق.
5. دفع المصروف من التطبيق ومشاهدة تحديث الإدارة فورًا.
6. تثبيت التطبيق أو الوصول إلى تعليمات التثبيت المناسبة للجهاز.
7. تبديل AR/EN دون كسر الاتجاه أو فقدان الحالة.

## 13. النشر والتسليم

- مستودع GitHub عام باسم `jeerah-smart-demo` ما لم يطلب المستخدم جعله خاصًا قبل النشر.
- لا توضع أي أسرار أو بيانات دخول للموقع المرجعي في المستودع.
- GitHub Actions يبني المشروع وينشر النسخة الثابتة إلى GitHub Pages.
- README عربي/إنجليزي يشرح التشغيل، حسابات الديمو الآمنة، التثبيت، وحدود النسخة.
- رابط تجربة مباشر، رابط المستودع، وتعليمات مختصرة لإضافة التطبيق إلى الشاشة الرئيسية.
- تبقى جميع الدفعات والإشعارات والبيانات ضمن المتصفح ولا تتصل بأنظمة إنتاج.

## 14. خارج النطاق

- خادم إنتاج أو قاعدة بيانات سحابية.
- خصم مالي حقيقي أو Merchant setup لـ Apple Pay/mada/Visa.
- رسائل SMS/Email/Push حقيقية.
- نظام صلاحيات أمني صالح للإنتاج.
- رفع ملفات إلى تخزين خارجي أو معالجة مستندات حقيقية.
- تكامل خرائط أو بوابات دخول فعلية.

هذه الحدود لا تمنع التجربة من الظهور والعمل كمنتج متكامل؛ بل تمنع فقط الاتصالات الخارجية والعمليات غير المناسبة لنسخة العرض.

## 15. قرارات محسومة

- الاتجاه البصري المعتمد هو Living Neighborhood الداكن والحيوي.
- الأيقونات الوظيفية من Phosphor Duotone، وشعارات الدفع من أصول رسمية.
- الدفع محاكاة واقعية وآمنة، وليس خصمًا حقيقيًا.
- بيانات الديمو خيالية وقابلة لإعادة الضبط.
- التطبيق والإدارة يشتركان في مصدر بيانات محلي واحد ويتزامنان بين التبويبات.
- التطبيق PWA قابل للتثبيت، والإدارة متجاوبة بالكامل.
- النشر الافتراضي عام عبر GitHub Pages لتوفير رابط تجربة مباشر.
